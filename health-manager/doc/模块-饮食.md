# 模块 — 饮食

> 本文件是饮食模块的权威产品设计文档，照着它实现。

## 产品定位

饮食模块记每天吃了什么（食物 + 量）、多少卡、三大宏量营养素（碳水/蛋白质/脂肪），看能量与营养摄入的趋势，并支持卡路里目标和宏量目标。

## 数据范畴

| 数据 | 类型 | 录入方式 | 呈现 |
|---|---|---|---|
| 饮食记录 | 事件流（一样食物 / 一顿饭） | 对话口述 | 今日清单（按餐分组）+ 每日总卡路里趋势 |
| 宏量营养素 | 每条记录附带的数字 | Agent 估算 | 当日合计 + 进度条比对目标 |
| 卡路里目标 | 静态设置 | 设置页 / 对话 | 卡路里环 |
| 宏量目标 | 静态设置（自动派生或手动） | 设置页 | 进度条 |

一条记录：日期 + 餐别（早餐/午餐/晚餐/加餐）+ 食物 + **量（文本）** + 卡路里 + **碳水/蛋白质/脂肪（克）** + 备注。

## 交互模型

### 对话录入（唯一通道）

- 「中午吃了一碗牛肉面」→ record_diet（卡路里与营养素机制见下方）

记录返回**当日累计卡路里**，Agent 顺带一句「今天目前一共 1850 卡」。

### 卡路里和营养素怎么来的

饮食模块是单向流入，用户喂数据的**唯一通道是和 Agent 聊天**（没有表单、没有 App 反向通知）。卡路里和营养素都不需要用户每次报数字：

- 用户报了数字 → 直接用。
- 用户没报 → **Agent 用语言模型的常识自行估算**（「牛肉面大概 600 卡、碳水 70g、蛋白质 25g」），在聊天里说一句确认后录入。

这不是额外机制，就是 Agent 在标准的「聊天 + 工具调用」循环里，调 `record_diet` 时自己把 calories / carbs / protein / fat 参数填上。

**工具描述必须授权 Agent 估算**：`record_diet` 的说明里要写明「用户没报时，根据食物自行估算合理值」。否则 Agent 看到参数缺失可能会卡住或反过来逼用户给数字。

### 量怎么来的

量（quantity）是**宽松文本**，由 Agent 从对话里抓取：

- 「一碗牛肉面」→ quantity=`1碗`
- 「半盘沙拉」→ quantity=`半盘`
- 「两个鸡蛋」→ quantity=`2个`

没有固定单位，不参与计算，只作展示。用户没提量就不填。

### 营养素

- 碳水 / 蛋白质 / 脂肪：**数字、公制（克）**，录入时必填——用户没报时 Agent 必须估一个合理值填入，不能留空（前端营养环靠这三个数填充）。能跨三餐加总。
- **纤维**：不做。
- **维生素**：不做结构化列，由 Agent 写进每条记录的备注里（如「维C 丰富」），纯文本、不汇总。

## 目标系统

目标决定首页和详情页的环形图填充。分两种，由 `goal_mode` 控制：

### 自动模式（默认）

服务端从卡路里目标按标准比例派生宏量目标：

- 碳水：卡路里目标 × 50% ÷ 4 kcal-g
- 蛋白质：卡路里目标 × 25% ÷ 4 kcal-g
- 脂肪：卡路里目标 × 25% ÷ 9 kcal-g

例：2000 卡 → 碳水 250g / 蛋白质 125g / 脂肪 56g。用户改了卡路里目标，三个宏量目标自动重算。

卡路里目标未设置时，宏量目标也为空。

### 手动模式

用户在设置页直接填三个克数，覆盖自动值。

### 进度填充

目标决定首页摘要卡的填充。卡路里环 = 当日卡路里 ÷ 目标；每条宏量进度条 = 当日实际克数 ÷ 目标克数，均封顶 100%。

## 数据存储

- `diet_entries(id, date, meal, food_text, quantity, calories, carbs_g, protein_g, fat_g, note, created_at)`

`meal` 取值：breakfast / lunch / dinner / snack。`quantity` 为宽松文本，三营养素为 REAL（克）。列允许空（历史数据/兼容），但 `record_diet` 录入时三大宏量必填。

每条记录带自增 `id`，Agent 可按 id 增删查改：record_diet 增、get_diet_log 查（每条返回带 [编号]）、update_diet 改（patch，只动传入字段）、delete_diet 删。

目标存 `settings` 表：`goal_mode`（auto/manual）、`carb_goal` / `protein_goal` / `fat_goal`（仅手动模式生效）。

## MCP 工具

| 工具 | 用途 |
|---|---|
| record_diet | 记一条饮食（食物 + 量 + 卡路里 + 三大宏量），三大宏量必填，返回当日累计卡路里 |
| get_diet_log | 查某天的饮食清单，每条带 [编号] |
| update_diet | 按编号修改一条饮食（patch，只动传入字段），常用于补填宏量 |
| delete_diet | 按编号删除一条饮食 |
| set_diet_goals | 设饮食目标（卡路里 / 三大宏量），部分更新，三个宏量需同时给 |
| get_diet_goals | 查卡路里目标 + 三大宏量目标（含自动/手动模式） |

宏量目标的「自动/手动」模式：填了宏量目标即切到手动模式；只设卡路里目标时宏量由卡路里自动派生。模式切换也可走设置页（WS）。

## Notification 设计

不需要 Notification，数据从对话单向流入。

## UI 设计

### 饮食 tab

顶部摘要卡（左：卡路里细环，中心当日千卡；右：碳水/蛋白质/脂肪三条进度条，条上标「已吃 / 目标 g」）+「今天吃了」（按餐分组）+ 卡路里趋势图。趋势卡顶部带周/月切换，卡内底部放「查看历史」入口。顶部**不带目标编辑按钮**，目标统一在设置页改。

### 历史页

每日记录列表**默认折叠**（日期 + 三大营养素合计 + 总卡）。点某一天 → 该天就地展开，用 `MealList` 展示当餐明细。历史页不放趋势图，图只在饮食 tab。

### MealList（共用组件）

按餐别分组渲染：每个餐别一个小标题（含该餐小计）+ 食物行（「食物 · 量 … 卡路里」）。饮食 tab 的「今天吃了」和历史页的当日展开共用此组件。

摘要页放「今日卡路里」卡。

## 校对

- **硬规则**：卡路里单条 0–5000；碳水/蛋白质/脂肪单条各自 0–500g；目标各自 0–1000g。超范围工具直接拒绝。
- **软校对**：Agent 估算时给出区间，让用户确认取哪个值。

## 技术架构

复用双通道。WS 快照 `diet: { entries, goal, goalMode, macroGoals }`，其中 `macroGoals` 为按当前模式解析后的 `{ carbs, protein, fat }`。
