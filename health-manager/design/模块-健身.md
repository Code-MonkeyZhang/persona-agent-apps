# 模块 — 健身

> 本文件是健身模块的权威产品设计文档，照着它实现。

## 产品定位

健身模块记两件事：运动日记（每次练了什么）和能力记录（各动作的最好成绩）。
默认视图是运动日记——用 GitHub 风格的贡献图回看训练频率和消耗。能力记录在第二个 tab，看自己力量怎么涨。

## 数据范畴

| 数据 | 类型 | 录入方式 | 呈现 |
|---|---|---|---|
| 运动日记 | 事件流（某次训练内容） | 对话口述 | 贡献图打卡 + 按日期的训练明细 + 当日总消耗 |
| 能力记录 | 动态指标（某动作最好成绩） | 对话口述 | 能力列表 + 单动作进步趋势折线 |

- 运动日记：日期 + 动作 + 组数 + 次数 + 重量（可选）+ 消耗卡路里 + 感觉（可选）。
- 能力记录：动作名 + 指标（最大重量 / 最多次数，可扩展）+ 值 + 日期。

## 交互模型

### 对话录入（唯一通道）

- "深蹲现在能蹲 100 了" → record_strength
- "今天练了胸：卧推 4 组 x 8 个 60kg、飞鸟 3 组 x 12 个，感觉不错" → record_workout（Agent 拆成多条）
- 消耗卡路里用户没报时，Agent 根据动作和强度自行估算。

能力记录记完返回「本次 + 上次 + 变化量」，Agent 直接回"上次 95，涨了 5"，不用再调一次查询。

### 打卡

无单独打卡按钮。某天有运动日记即视为那天练了，日记页的贡献图自动打点。

## 数据存储

- `strength_records(id, date, exercise, metric, value, unit, note, created_at)`
- `workout_entries(id, date, exercise, sets, reps, weight, calories, feeling, note, created_at)`

动作名为自由文本，第一次出现即建档，不预先配置。

## MCP 工具

| 工具 | 用途 |
|---|---|
| record_strength | 记一条能力成绩，返回比上次的变化 |
| record_workout | 记运动日记（支持一次多个动作） |
| get_strength_history | 查某动作的能力历史（画趋势 + Agent 查询） |
| get_workout_diary | 查最近的运动日记 |

## Notification 设计

健身模块不需要 Notification，数据从对话单向流入。

## UI 设计

健身 tab 顶部「日记 / 能力」分段切换，日记为默认。

- **日记**（默认）：GitHub 风格贡献图（近 13 周，绿格=有训练，深浅按消耗卡路里分级），点某天进入当天训练明细（动作列表 + 总消耗）。下方保留最近 7 天精简列表，也可点入当天详情。
- **能力**：按动作列最好成绩卡（最新值 + 带色变化标签 + 小趋势线），点进看该动作进步折线 + 历史（新高/起点标签 + 进步总结条）。

摘要页放"最近一次能力进步"卡，点进跳健身模块。

贡献图和日历均由 `react-activity-calendar` 库渲染，日记/能力钻入用方向感知 push/pop 转场。

## 校对

- **硬规则**（工具内部）：能力值 / 组数 / 次数 / 重量设防离谱范围。
- **软校对**（Agent）：成绩异常波动（比如一次涨 20kg）主动确认"变化有点大，确认是这个数吗"。

## 技术架构

复用现有双通道（stdio MCP + uvicorn HTTP + WebSocket 全量快照）。
WS 快照按模块命名空间，健身模块加 `fitness: { strengthRecords, workoutEntries }`。
