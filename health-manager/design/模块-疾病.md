# 模块 — 疾病

> 本文件是疾病模块的权威产品设计文档，照着它实现。

## 产品定位

疾病模块管两件事：结构化的化验数据与定性的病历记录。普通用户拿着化验单和就诊经历来，Agent 把它变成能看懂的趋势和拿得出手的就医材料。

一期范围是化验数据、影像病理结论与病历。化验单图片归档与识别留在二期，本期不做。

边界：不给医疗诊断，不替用户做健康决策。Agent 只记录数据、描述已记录数据里的规律，指标解释和对比都停在这一层。

## User Story

### 第一次打开

- 作为刚下载 App 的用户，我想知道疾病模块能帮我做什么、从哪一步开始，以便决定要不要把健康数据交给它
- 作为没有任何医学背景的用户，我希望零门槛开始记录，不需要先搞懂什么是肌酐

### 记化验

- 作为刚拿到化验单的用户，我想把上面的指标念给 Agent，它负责存成结构化数据，以便我不用打字建表
- 作为念完指标的用户，我想马上知道哪几项超出参考范围，以便不用自己逐行对箭头
- 作为定期复查的用户，我想每次复查后把新结果追加进去，以便几次之后就攒出自己的趋势线
- 作为看不懂术语的用户，我想让 Agent 用大白话解释某项指标是管什么的，以便下次看到不再一头雾水

### 记病历

- 作为看完病的用户，我想把诊断、用药、医嘱口述给 Agent 让它整理成病历，以便下次就诊前能想起来
- 作为用户，我想自己补充病历，也让 Agent 帮我维护，以便人和 Agent 都能往里写

### 看数据

- 作为用户，我想选一个指标看它历次变化的曲线和参考范围，以便知道自己在好转还是变差
- 作为用户，我想问 Agent 这次和上次比哪里变了，以便不用对着两张单子自己比
- 作为用户，我想让 Agent 点出哪些指标一直不正常，以便长期盯着重点
- 作为用户，我想打开 App 首页就看到当前最该留意的异常，以便不漏掉重要信号

### 去医院

- 作为快复诊的用户，我想让 Agent 整理一份近期指标变化加病情摘要，以便带一份现成材料给医生

### 纠错

- 作为录错数的用户，我想让 Agent 改掉或删掉错误记录，以便历史长期可信

### 二期占位

- 作为用户，我想拍下化验单让它自动识别录入，以便连数字都不用念
- 作为用户，我想把报告原件照片存档，以便随时翻原始单据

## 数据范畴

| 数据 | 类型 | 录入方式 | 呈现 |
|---|---|---|---|
| 化验结果 | 数值或定性文字，按指标与日期 | 对话口述，批量一次化验 | 按大类分组的指标卡 + 单指标趋势与历史 |
| 影像病理结论 | 一次检查的成段文字 | 对话口述 | 按日期的结论卡片 |
| 病历 | 按日期一文件的 markdown | 人机共写 | 日期卡片 + 界面编辑器 |
| 化验单图片 | 二期 | 依赖平台发图与模型多模态识图 | 二期设计 |

化验指标按大类组织，沿用存量数据的分组：生化检查、尿液检查、血液常规、免疫检查、内分泌检查、其他检查。

## 交互模型

### 记化验（对话，唯一通道）

- 用户念化验单：「肌酐 106，尿素 9.51，尿蛋白 2 加」→ Agent 调 record_lab_result 批量录入
- 指标名支持口语与缩写：肌酐、血肌酐、Scr 都归到同一指标，归一靠包内字典
- 录完返回每项的参考范围对比、偏高偏低标记、与上次的变化，Agent 直接转述
- 指标名不确定时 Agent 先调 list_lab_analytes 核对标准名
- 念错了说一声，Agent 按编号 update 或 delete 单条，不用整次重录

### 记影像病理（对话）

- 用户口述检查所见或诊断印象 → record_imaging_finding 存日期、检查类型与结论原文

### 记病历（人机共写）

- 对话口述就诊经过，Agent 整理后调 update_health_journal 写入对应日期
- 界面病历卡片带编辑器，用户可直接改原文或新写一篇，两条写入口共用同一落盘与快照逻辑

### 边界

- Agent 不做诊断推断、不给用药建议，解释指标只用大白话描述已记录的数据

## 数据存储

- `lab_results(id, date, specimen, category, analyte, value_num, value_text, unit, ref_low, ref_high, ref_text, abnormal_flag, note, created_at)`
- `imaging_findings(id, date, exam_type, finding_text, image_ref, note, created_at)`，image_ref 一期建好留空，二期挂图片路径
- 单位与参考范围一律记录级保存，化验单上带了就存单据的，没带用字典兜底
- 病历是文件不是表：`data/journal/{date}.md` 按日期一文件，文件名即时间线；写前自动快照到 `data/journal_snapshots/`，每个文件保留最近 5 份
- 指标字典是版本化资产 `src/health_manager/analytes.py`：169 个指标的标准名、大类、默认单位、兜底参考范围、别名、极值界。它是代码不是个人数据，随 App 发布
- 异常标记一律由工具按记录级参考范围判定落库，化验单自带的 H/L 不作依据；数值有且范围有才判，否则留空
- 存量数据走一次性脚本 `scripts/import_legacy.py`：化验与影像入库、旧病历按日期拆分、行数核对、极值抽查、重算标记与单据标记不一致的行输出人工抽查，settings 落 disease_imported 标记防重复

## MCP 工具

| 工具 | 用途 |
|---|---|
| record_lab_result | 批量录一次化验，自动归一、判偏高偏低，返回逐项对比 |
| get_lab_history | 查某指标全部历史，每条带 [编号] |
| list_lab_analytes | 按大类列已录指标与最新值，录入前核对名字用 |
| update_lab_result | 按编号改一条（patch），改完自动重算标记 |
| delete_lab_result | 按编号删一条 |
| record_imaging_finding | 录一条影像病理结论 |
| get_imaging_history | 查影像病理，按时间倒序，可按类型过滤 |
| get_health_journal | 读病历，不带日期返回索引，带日期返回全文 |
| update_health_journal | 写或覆盖某日病历，写前自动快照 |

## Notification 设计

一期不需要。数据从对话单向流入，界面上改病历也不回头通知 Agent，Agent 要最新就读工具。二期图片流程若引入异步环节再补 Notification 设计。

## UI 设计

### 疾病 tab

顶部三段切换：化验 / 影像病理 / 病历。

- 化验：按六大类分组的指标卡网格，每卡显示最新值、单位、偏高偏低徽标、比上次变化与迷你趋势线。点卡片进指标详情：趋势图带绿色参考带、超出参考范围的点标红标蓝，下方是按日期排列的历史列表
- 影像病理：按日期倒序的结论卡片，含检查类型徽标与结论原文
- 病历：按日期倒序的卡片，标题取正文一级标题，正文原文展示；卡片带编辑按钮，底部有写病历入口，编辑器是日期加正文的极简形态

### 摘要页

化验异常置顶卡：最新值超出参考范围的指标数，标「需关注」，点击进疾病 tab。一句话状态在血压之外新增化验异常话术。

### 空态

三个子视图各自的空态文案都指向对话，引导第一次口述。

## 校对

- 硬规则：字典极值界拒绝离谱值，超出直接拒绝录入
- 软校对：Agent 看到录入返回的偏高偏低与变化幅度，自行提醒用户
- 定性项（阴性、2+ 等）不判定标记，原样保存

## 技术架构

复用双通道。WS 快照 `disease: { labResults, imagingFindings, journal }`，全量推送与其他模块一个套路。演示模式切换时化验影像读 mock 库、病历读 `data/journal.mock/`，真实病历目录不被动。
