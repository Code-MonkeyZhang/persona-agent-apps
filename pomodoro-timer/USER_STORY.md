# 番茄时钟 Agent App 用户故事

> 本文是 session 模型改版定稿后的用户故事，只收故事与行为契约，机制与协议见 PRD.md。

## 一句话定位

番茄时钟是一个专注计时 Agent App。用户一次设定工作时长、休息时长和轮数，点开始后 session 完整自动跑完。Agent 在 session 开始和结束时收到通知，专注期间进入守护模式，不去打扰用户。

## 用户视角

用户在开始一次专注前把三个数一次配齐。工作多少分钟，休息多少分钟，跑几轮，再写一句意图说明这次要做什么，然后点开始。从这一刻起到 session 结束，用户不需要再碰任何按钮。工作结束自动进入休息，休息结束自动开始下一轮，全部轮次走完才回到待开始状态。

用户中途可以暂停、继续、停止。暂停只是冻结计时，停止会中止整个 session，已经专注的部分时长记进历史并标为中断。

用户在历史页看到月历，有专注的日子带标记，点某天能看到当天的记录明细。用户也可以在对话里问 Agent 这周专注得怎么样，Agent 查询后用自然语言回答。

用户专注的时候知道 Agent 在守护。跑题闲聊会被温和提醒，平时它不出声。

用户还能在对话里让 Agent 起一个完整 session。说一句“工作 50 分钟休息 15 分钟跑两轮”，Agent 一次调用就配齐，不需要用户再自己去面板补设置。

## Agent 视角

Agent 调用 start 工具时每次必须传全 focus_min、break_min、rounds 三个参数，没有不传用默认值的后门。一次调用就起完整 session，不需要在轮间手动接力提醒用户按开始。

session 开始的通知让 Agent 进入守护模式，session 结束的通知让它解除。轮间切换轮不到 Agent 说话，计时和续轮由 App 自己完成。

Agent 能调 stop 中止 session，能调 query_stats 和 get_timer_state 查数据。纯查询不改变通知归属。专注记录也不需要 Agent 调工具，后端自动落库。

## App 角色

App 扮演管家。它持有 session 状态机，按配置自动推进轮次，在 session 开始和结束两个节点推 MCP notification，每段工作自动写进 SQLite，再通过 WebSocket 把状态同步给面板。

## 行为契约

通知路由按任务记账。启动 session 的那个 session 收走全部通知，中途查询不抢归属，目标 session 已删除时通知直接丢弃，不回退到别的 session。

通知是模式切换信号。session 开始进守护，结束出守护。Agent 自己调用 start 也收到通知，因为它同样需要知道自己进入了守护模式。

下面这些操作不触发通知。

- 暂停与继续
- 轮间自动切换
- 修改配置
- 查看历史
- 纯查询工具

App 不评价用户的专注质量，也不主动给生产力建议。

## 非目标

- 不做专注质量打分与生产力建议
- 不在轮间打扰用户
- 不依赖 Agent 做计时接力或记录
