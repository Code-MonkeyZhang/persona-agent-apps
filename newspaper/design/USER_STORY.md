# 报纸 newspaper · User Story

> 状态：设计定稿，待开发。本文只收 User Story 与已定决策，完整需求见同目录 PRD.md。
> 规划目录：agent-apps/newspaper，Python 包名 newspaper_app，显示名报纸。

## 一句话定位

报纸是一个新闻阅读器 Agent App。它自己不采集信息，内容由 Agent 配合采集类 skill 总结成短文后通过 MCP 工具逐条写入；用户在报纸风的界面里阅读，头版扫标题，文章页读正文，左右滑动翻页。

## 已定设计决策

| 决策点 | 结论 |
| --- | --- |
| 交互模式 | 翻页式。左滑下一条，右滑上一条，翻过的自动记已读 |
| 内容密度 | 每条新闻是一篇短文，标题加一到两段报道体正文 |
| 版面结构 | 头版为入口，含报头、头条截断、要闻索引、版面筛选、往期入口 |
| 期的归档 | 按自然日自动归期，跨天首次写入自动开新期 |
| 报名 | 首次写入时通过 paper_name 指定，之后沿用 |
| Agent 通知 | 第一版不设计任何 notification，App 保持安静 |
| 空状态 | 只做文案引导，不放采集请求按钮 |
| 双端 | 桌面网页与手机同时支持，手机为单栏窄版 |

## 读者视角

- 作为读者，我打开 App 看到今天的报纸头版，报头有报名、日期与期号，第一眼知道这是第几期
- 作为读者，我能在头版看到头条标题与正文开头截断，点阅读全文进入整页文章
- 作为读者，我能在要闻列表一屏扫完当期全部标题，点任意一条直接进入该文章
- 作为读者，我在文章页读完一到两段完整正文，左右滑动在文章间翻页，翻过的自动记已读
- 作为读者，每篇文章页有来源与原文链接，点链接能跳到原文
- 作为读者，我能按版面筛选内容，版面名来自新闻自带的 tag
- 作为读者，我能翻看往期报纸，看到每期几条、是否读完
- 作为读者，当期为空时我看到尚未投递的引导，知道该去对话里叫 Agent 采集
- 作为读者，我在手机和桌面网页上都能读报，手机是单栏
- 作为读者，Agent 正在投递时我打开的页面实时出现新文章，不需要手动刷新

## Agent 视角

- 作为 Agent，我能通过 add_news 逐条写入新闻，字段含标题、正文、来源、链接、版面 tag
- 作为 Agent，我写入的正文按报纸文章体呈现，一到两段成文，不是一句话摘要
- 作为 Agent，我能通过 query_news 查询当期状态，知道今天已投几条、报名是什么
- 作为 Agent，我能通过 clear_edition 清空当期重新投递
- 作为 Agent，我的写入当场返回结果，不需要等事后通知

## 非目标

- 不做表态回流。右滑不是感兴趣，没有偏好收集
- 不做原文抓取与站内全文阅读，原文链接跳出
- 不做评论、分享、收藏
- 不做多报名多订阅，第一版只有一份报

## 附录：工具面与通知结论

工具三个，每个只干一件事。agentId 与 sessionId 由平台注入，工具定义里标可选。

| 工具 | 参数 | 行为 | 返回 |
| --- | --- | --- | --- |
| add_news | title、body 必填，source、url、tags、paper_name 可选 | 写入当期。当期不存在则自动开期并记录当次 agentId 与 sessionId | 期号、当期条数 |
| query_news | 无 | 纯查询，不改当期归属 | 期号、日期、条数、已读未读数、报名、最近写入的标题 |
| clear_edition | 无 | 清空当期，已读状态一并清掉 | 成功回执 |

通知结论。按设计原则逐条核对：没有后台异步任务，add_news 同步完成当场返回，后台事后通知一条都不需要；界面操作逐个过了一遍，翻页、点原文、切版面、看往期都是本地状态，不回流 Agent。空状态的采集请求按钮留到二期，原因是首次使用时从没有过投递，App 手里没有可投递的 session，通知路由无法成立。

当期在首次写入时记录 agentId 与 sessionId，按事情记账，为二期可能的采集请求通知预留。若二期引入通知，四字段 agentId、sessionId、source、content 缺一不可，sessionId 不许留空。

技术栈按统一规范：后端 Python 加 uv，双通道先起 HTTP 再起 MCP，stdout 不写日志；前端 React 加 Vite，图标 Lucide，组件 shadcn；持久化用 SQLite；构建产物进 ui 目录随仓分发。
